# rnm v0.2.0 更新文档

## 新特性与改进

### 1. 优化递归搜索机制

-   重新设计了目录遍历逻辑，更智能地处理递归搜索
-   当遇到 `node_modules` 目录时会立即停止当前路径的递归
-   添加了防止重复访问目录的机制

### 2. 深度控制优化

-   移除了原有的 recursive 参数
-   使用 `--depth` 参数直接控制递归深度
    -   `--depth 0`: 无限递归
    -   `--depth N`: 递归 N 层目录

### 3. 性能优化

-   优化了目录遍历性能
-   减少了不必要的文件系统操作
-   添加了目录访问缓存机制

### 4. 预留功能

-   保留了包管理器缓存目录相关功能，为后续版本扩展做准备：
    -   npm 缓存目录支持
    -   yarn 缓存目录支持
    -   pnpm 缓存目录支持

## 使用方法

```bash
# 基本使用
rnm

# 指定目录深度
rnm --depth 2

# 指定起始目录
rnm --dir /path/to/project

# 列出要删除的目录
rnm --list

# 排除特定路径
rnm --exclude "**/test/**/node_modules"

# 强制删除（不询问确认）
rnm --force

# 查看详细输出
rnm --verbose

# 模拟运行（不实际删除）
rnm --dry-run
```

## 命令行参数说明

| 参数                  | 说明                               |
| --------------------- | ---------------------------------- |
| `--dir <DIR>`         | 指定要删除 node_modules 的目录路径 |
| `--depth <N>`         | 设置递归深度（0 表示无限递归）     |
| `--exclude <PATTERN>` | 排除特定路径（支持 glob 模式）     |
| `--force`             | 强制删除，不进行确认               |
| `--dry-run`           | 模拟删除，不实际执行               |
| `--verbose`           | 显示详细输出                       |
| `--list`              | 列出要删除的路径                   |

## 注意事项

1. 建议首次使用时先使用 `--list` 参数查看将要删除的目录
2. 使用 `--dry-run` 可以安全地测试删除操作
3. 深度设置为 0 时将进行完整递归搜索
4. 排除模式使用 glob 语法，可以灵活指定要排除的路径
